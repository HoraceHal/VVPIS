# 实现计划与架构

## 需求落地

1. 将现有最终运行方案参数化，不复制服务器快照、账号、密钥、机场订阅或数据库。
2. 用交互菜单覆盖初装、继续安装、地址查询、端口说明、健康检查、证书续期、直出/混合和清理。
3. 保留 3x-ui 原版订阅前端；移除旧定制页面及其独立设备管理服务。
4. 用固定版本、SHA256、端口与系统预检减少安装漂移；已有服务不被无声覆盖。
5. 使用本机小型适配服务保留 QX、Hysteria2 的鉴权和合计用量；减少重复服务。
6. 将检查分为纯单测、真实配置校验、临时 VM 的完整安装与端到端连接。
7. 在公开发布前检查 Git 的实际暂存文件与现网敏感值。

## 数据路径

```text
客户端
  ├─ TCP 443 → Xray/Trojan ──────────────┐
  ├─ UDP 443 → Hysteria2 ────────────────┤
  │                                    ↓
  │                           本机有鉴权的 Mihomo
  │                             ├─ 固定服务器直出
  │                             └─ 服务器优先 → 机场备用
  │
  └─ HTTPS 443 → Xray TLS fallback → Nginx
                                     ├─ 随机路径 → 3x-ui 后台
                                     ├─ /sub/令牌 → 3x-ui 原版前端 + 统计衔接
                                     └─ 指纹静态资源 → 压缩和缓存
```

公网仅需已有 SSH、TCP 80/443、UDP 443。面板、订阅源、统计、SOCKS 和控制 API 均只监听本机。

## 凭证与数据

- 安装状态 `/etc/vvpis/state.json`，root 0600。
- 3x-ui 数据库 `/var/lib/vvpis/x-ui/`。
- Hysteria2 持久化计数 `/var/lib/vvpis/subscriptions/`。
- Hysteria2、订阅适配、出口网关分别使用独立系统用户。
- 域名作为 TLS 验证名，节点首跳仍为该机器的公网 IPv4，避免代理 DNS 解析首跳时形成循环。
- 原版页面的累计用量合计两个协议；3x-ui 原生面板计数仍以 Xray/Trojan 为主。

## 可用性设计

- IP 证书有效期短，按小时检查续期；续期后同步 Hysteria2 文件，Xray 按自身机制重新读取证书，不为前端或证书同步重启现有隧道。
- 监控分开记录本地故障与外网不可达。外网探测失败只报告，不重启整套服务。
- 本地连续两次失败后才恢复；同一服务至少间隔 15 分钟，每小时最多两次，每轮最多恢复两个服务。
- 统计取样不清空 Hysteria2 生产端计数，使用进程代际与累计差分避免重复累计。
- 默认没有周期备份，也不定时“清洗 IP”或频繁更换出口。

## 以后扩展

更多地区需要新增实际服务器或合法出口。每台机器独立安装后，可把各自节点纳入已有管理体系；本安装器不会把单机不同协议显示成虚假的不同地区。
